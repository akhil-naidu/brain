title: Local setup
description: Install Brain locally with Git, Node 24, pnpm, Docker, and a model.

Install the tools, clone the repo, start Postgres, create an operator account, and send a chat. After each command, run the **Check**. Skip a step if that check already passes.

Pick **macOS**, **Windows**, or **Linux** in the tabs. The choice sticks for the rest of this page.

No Vercel account, Neon, or Vercel AI Gateway.

## 0. What Brain needs

| Piece | What it is |
| --- | --- |
| **Git** | Clone the Brain source |
| **Node 24** | Runtime. This guide installs it with nvm |
| **pnpm** | Package manager. Do **not** use npm or yarn |
| **Docker** | Runs Postgres |
| **A model** | Ollama or `COMMAND_CODE_API_KEY` |

## 2. Compiler tools and Git

<Tabs groupId="os" items={['macOS', 'Windows', 'Linux']} persist>
<Tab value="macOS">

Apple’s Command Line Tools include a compiler. Git often comes with them.

```bash
xcode-select --install
```

A system dialog may appear. Click **Install** and wait. If it says already installed, continue.

**Check** — you should see a path, not an error:

```bash
xcode-select -p
```

Typical output: `/Library/Developer/CommandLineTools` or a path under `/Applications/Xcode.app`.

Homebrew is a package manager. Use it if Git is missing.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Enter your Mac password if asked (you will not see characters as you type). Wait until it finishes.

On **Apple Silicon** (M1/M2/M3/M4) the installer often says Homebrew is not on your `PATH`. Paste these **two** commands, one at a time:

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
```

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```

On **Intel Macs**, use `/usr/local/bin/brew` instead of `/opt/homebrew/bin/brew` if the installer printed that path.

**Check**

```bash
brew --version
```

You should see `Homebrew 4.x` (or similar), not `command not found`.

## 5. pnpm

**pnpm** installs the project’s JavaScript dependencies. Brain **blocks npm and yarn** — if you run `npm install` it will error on purpose.

```bash
corepack enable
```

```bash
corepack prepare pnpm@11.13.1 --activate
```

**Check**

```bash
pnpm --version
```

You need **11** or higher (11.13.1 is what the repo pins).

## 6. Docker

Docker runs **Postgres** (Brain’s database) in a container. You do not install Postgres by hand.

<Tabs groupId="os" items={['macOS', 'Windows', 'Linux']} persist>
<Tab value="macOS">

1. Open [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)
2. Download **Docker Desktop for Mac** (Apple Silicon or Intel — match your laptop)
3. Open the installer and drag Docker to **Applications**
4. Open **Docker** from Applications (whale icon in the menu bar)
5. Accept the service agreement if asked
6. Wait until the whale is steady and the app says **Engine running**

</Tab>
<Tab value="Windows">

4. In Docker Desktop → Settings → Resources → WSL integration, turn on **Ubuntu**
5. Wait until it says **Engine running**
6. Run Docker commands from the **Ubuntu** terminal, not PowerShell

Leave Docker Desktop **open** whenever you use Brain.

</Tab>

```bash

```

## 9. Install JavaScript packages

You must be **inside** the `brain` folder. Turn on Node 24 for this window:

```bash
cd ~/dev/brain
```

```bash
nvm use
```

```bash
node -v
```

Must still be `v24.x`. Then:

```bash
corepack enable
```

```bash
pnpm install
```

This can take several minutes. Lines about Fumadocs / `postinstall` are normal.

**Check:** the command ends with no error, and this prints a path:

```bash
ls node_modules
```

If you see `Use pnpm to install`, you used `npm install`. Stop. Use `pnpm install` only.

## 10. Start Postgres

Docker must be running. From the `brain` folder:

```bash
docker compose up -d db
```

Wait a few seconds.

```bash
docker compose ps
```

The `db` row should look **running** or **healthy**.

```bash
docker compose exec db pg_isready -U brain -d brain
```

Should print `accepting connections`.

This creates:

- Database `brain` — user `brain`, password `brain` (the app)
- Database `brain_test` — for automated tests only (will not wipe your login)

If port **5432** is already used by another Postgres: stop that other Postgres, or change the host port in `docker-compose.yml` and use the new port in `BRAIN_DATABASE_URL`.

## 11. Create `.env`

This file holds secrets. It is **not** committed to Git.

From the `brain` folder:

```bash
cp .env.example .env
```

Generate a **session** secret. Copy the whole line of output (letters, numbers, `+`, `/`, `=`):

```bash
openssl rand -base64 32
```

Generate a **bootstrap** secret. Run this **again** so you get a **different** string:

```bash
openssl rand -base64 32
```

Open `.env` in an editor. These next boxes are **lines to paste into that file**, not commands for the shell. Paste your two openssl outputs. Do not reuse one string for both secrets.

<Tabs groupId="os" items={['macOS', 'Windows', 'Linux']} persist>
<Tab value="macOS">

Cursor, VS Code, TextEdit, or:

```bash
nano .env
```

</Tab>
<Tab value="Windows">

In Ubuntu, use Cursor/VS Code with WSL, or:

```bash
nano .env
```

Save in nano with **Ctrl+O**, **Enter**, then **Ctrl+X**.

</Tab>
<Tab value="Linux">

Cursor, VS Code, or:

```bash
nano .env
```

Save in nano with **Ctrl+O**, **Enter**, then **Ctrl+X**.

</Tab>
</Tabs>

```ini
BETTER_AUTH_SECRET=paste-first-openssl-output
```

```ini
BRAIN_BOOTSTRAP_TOKEN=paste-second-openssl-output
```

```ini
BRAIN_DATABASE_URL=postgres://brain:brain@127.0.0.1:5432/brain
```

```ini
BRAIN_PUBLIC_URL=http://localhost:3000
```

```ini
BETTER_AUTH_URL=http://localhost:3000
```

| Variable | Why |
| --- | --- |
| `BETTER_AUTH_SECRET` | Signs your login cookie |
| `BRAIN_BOOTSTRAP_TOKEN` | You will paste this on `/setup` |
| `BRAIN_DATABASE_URL` | Points at Docker Postgres |
| `BRAIN_PUBLIC_URL` / `BETTER_AUTH_URL` | This laptop’s site origin |

Leave `COMMAND_CODE_API_KEY=` empty if you will use Ollama only.

Do **not** Slack or email these values.

**Check** — all five lines should print with values after `=`:

```bash
grep -E '^(BETTER_AUTH_SECRET|BRAIN_BOOTSTRAP_TOKEN|BRAIN_DATABASE_URL|BRAIN_PUBLIC_URL|BETTER_AUTH_URL)=' .env
```

### Optional later (not needed for first chat)

| Variable | When |
| --- | --- |
| `COMMAND_CODE_API_KEY` | Built-in models in the picker |
| `BRAIN_INTERNAL_TOKEN` | **Schedules only** — unattended timers. Another `openssl rand -base64 32` |
| `BRAIN_INTERNAL_URL` | **Schedules only** — already defaults to `http://127.0.0.1:3000` |
| MCP client ids | Only if you skip in-app Connect. [Environment](/docs/reference/environment) |

## 12. Run Brain

Still in the `brain` folder:

```bash
nvm use
```

```bash
pnpm dev
```

**Leave this Terminal running.** You should see Next.js ready on port **3000**.

Open a browser:

[http://localhost:3000](http://localhost:3000)

- Empty database → you go to **setup**
- Operator already exists → **sign-in**

If the page errors, read the `pnpm dev` window: Docker not running, empty `BETTER_AUTH_SECRET`, or wrong `BRAIN_DATABASE_URL` are the usual causes.

## 13. Create the operator account

1. Open [http://localhost:3000/setup](http://localhost:3000/setup)
2. Title should be **Create operator**
3. Fill in:
   - **Name** — how you want to appear
   - **Email** — you will sign in with this
   - **Password** — at least **8** characters
   - **Bootstrap token** — paste `BRAIN_BOOTSTRAP_TOKEN` from `.env` (exact match)
4. Click **Create account**

You land on **`/chat`**. Brain creates a [personal workspace](/docs/workspaces/overview). You are the **instance admin**. Other people stay invite-only until you change policy — [Accounts and sign-in](/docs/getting-started/accounts-and-sign-in).

If you see **Setup closed**, someone already created the operator. Use [http://localhost:3000/sign-in](http://localhost:3000/sign-in).

To wipe local users and start `/setup` again:

```bash
docker compose down -v
```

```bash
docker compose up -d db
```

Then open `/setup` again.

## 14. Ollama on a VPS (the model)

Brain sends chat to an **OpenAI-compatible** URL. Ollama provides that at `http://HOST:11434/v1`.

Your **laptop** must reach Ollama (discovery waits only **4 seconds**).

<Callout title="Keep Ollama private" type="info">
  On the VPS, leave Ollama on localhost. From the laptop, use an SSH tunnel. Do
  not open port 11434 to the whole internet for a first test.
</Callout>

### 14.1 On the VPS

From your laptop, log into the server (replace user and host):

```bash
ssh YOUR_USER@YOUR_VPS_HOST
```

Install Ollama:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

Download a model that fits the VPS RAM. Example:

```bash
ollama pull llama3.2
```

Smaller if RAM is tight: `llama3.2:1b`, `qwen2.5:3b`, `phi4-mini`.

**Check on the VPS**

```bash
ollama list
```

```bash
curl -sS http://127.0.0.1:11434/api/tags
```

You should see the model name in the JSON. Stay logged in or keep Ollama running as a service, then you can leave this SSH session.

### 14.2 On the laptop — SSH tunnel

This makes the VPS look like `127.0.0.1:11434` on your machine.

<Tabs groupId="os" items={['macOS', 'Windows', 'Linux']} persist>
<Tab value="macOS">

Open a **new** Terminal (**do not** stop `pnpm dev`).

</Tab>
<Tab value="Windows">

Open a **new** Ubuntu window (**do not** stop `pnpm dev`).

</Tab>
<Tab value="Linux">

Open a **new** terminal (**do not** stop `pnpm dev`).

</Tab>
</Tabs>

Paste (same user and host as above):

```bash
ssh -N -L 11434:127.0.0.1:11434 YOUR_USER@YOUR_VPS_HOST
```

`-N` means “forward ports only, no remote shell”. **Leave this window open.**

Open another terminal window and check:

```bash
curl -sS http://127.0.0.1:11434/api/tags
```

You should see the same JSON as on the VPS.

If that fails: tunnel window closed, Ollama down, or something else already using 11434 on this machine.

If 11434 is already used on the laptop, forward a different local port:

```bash
ssh -N -L 11435:127.0.0.1:11434 YOUR_USER@YOUR_VPS_HOST
```

Then in Brain use base URL `http://127.0.0.1:11435/v1`.

### 14.3 Alternative: public URL

Only if you cannot use a tunnel: bind Ollama to `0.0.0.0:11434` (`OLLAMA_HOST`), firewall **only your laptop IP**, and use `http://VPS_PUBLIC_IP:11434/v1` (or HTTPS). Prefer HTTPS + an allowlist.

## 15. Add Ollama in Brain

Stay signed in as the operator.

1. In the left sidebar click **Models**, or open [http://localhost:3000/models](http://localhost:3000/models)
2. Under **Start with a model**, click the **Ollama** card (or **Add model** if you already have models)
3. Fill the dialog:

| Field | What to enter |
| --- | --- |
| Who can use this? | **Entire instance** (all workspaces) or **This workspace** |
| Display name | `Ollama VPS` |
| Base URL | `http://127.0.0.1:11434/v1` (the `/v1` at the end matters) |
| API key | leave empty |
| Context window | `128000` |

4. Click **Fetch models** (next to Base URL)
5. Click the id you pulled (for example `llama3.2`) so **Model id** fills in
6. Click **Save**

The card should show **All workspaces** or **This workspace**, and **No key**. It should also appear under **Available in chat**.

If **Fetch models** fails: is the tunnel window still open? Did laptop `curl` to `/api/tags` work? Does the URL end with `/v1`? You can type **Model id** by hand from `ollama list` and still Save.

More: [Custom models](/docs/models/custom-models).

## 16. Send a test chat

1. Sidebar **New chat**, or [http://localhost:3000/chat](http://localhost:3000/chat)
2. In the composer, open the **model** menu and pick **Ollama VPS**
3. Set mode to **Ask** (plain reply, no tools) or leave **Agent**. **Shift+Tab** switches modes — [Ask vs Agent](/docs/chat/modes)
4. Paste this into the box:

```text
Reply with exactly: Brain is running.
```

5. Press **Enter**

A streamed reply means install worked. Next: [First chat](/docs/getting-started/first-chat).

**Chat isn't available** means no custom model and no `COMMAND_CODE_API_KEY`. Finish section 15, or add a Command Code key and restart `pnpm dev`.

Turn errors usually mean the tunnel dropped, the model id is wrong, the VPS is out of memory, or the base URL is missing `/v1`.

Local `pnpm dev` does not run the minute cron. Use **Run now** on `/schedules`. Production unattended runs need `BRAIN_INTERNAL_TOKEN` — [Schedules](/docs/playbooks-and-schedules/schedules).

## 19. Troubleshooting

| Symptom | What to do |
| --- | --- |
| `nvm: command not found` | Close the terminal and reopen. macOS: `source ~/.zshrc`. Windows/Linux: `source ~/.bashrc` |
| Wrong Node version | `cd` into `brain`, then `nvm use`, then `node -v` must be v24 |
| `Use pnpm to install` | Do not use npm. Run `corepack enable`, then `pnpm install` |
| Docker daemon error | Start Docker (Desktop on macOS/Windows, Engine on Linux) and wait |
| Database URL errors | `docker compose up -d db` and check `.env` |
| `/setup` says Setup closed | Operator exists → `/sign-in`. To reset: `docker compose down -v`, then `docker compose up -d db` |
| Bootstrap token rejected | Must match `BRAIN_BOOTSTRAP_TOKEN` in `.env` exactly |
| Chat unavailable | Save a custom model, or set `COMMAND_CODE_API_KEY` and restart `pnpm dev` |
| Fetch models / `ECONNREFUSED 11434` | Tunnel window must stay open; `curl` `api/tags` on the laptop |
| Fetch models empty | Type the id from `ollama list` by hand |
| OAuth redirect mismatch | `BRAIN_PUBLIC_URL` and `BETTER_AUTH_URL` must be `http://localhost:3000` |

If `brain_test` is missing (old Docker volume):

```bash
docker compose exec db psql -U brain -d brain -c 'CREATE DATABASE brain_test;'
```

Optional quality gate:

```bash
export BRAIN_DATABASE_URL=postgres://brain:brain@127.0.0.1:5432/brain
```

```bash
pnpm run verify
```

More: [Self-hosting troubleshooting](/docs/self-hosting/troubleshooting).
